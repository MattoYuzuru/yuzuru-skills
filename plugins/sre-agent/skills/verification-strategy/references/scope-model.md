# Scope and behavioral model

Choose one primary mode: focused feature, changed files/PR, subsystem, full project, release
candidate, staging/authorized production, performance, reliability, security, incident, or test
strategy.

Model actors and permissions, state transitions, invariants, data ownership, synchronous and
asynchronous boundaries, external dependencies, retry/idempotency behavior, and observability. Map
each important requirement or risk to evidence and each test to a cleanup rule.

State the revision and environment. Passing evidence from another revision or environment is
context, not proof for the target.
