# Implementation Plan Contract

Include:

- objective and acceptance criteria;
- relevant artifacts, modules, tests, and conventions;
- current behavior and root cause when fixing a bug;
- proposed behavior and affected public/data contracts;
- files or components likely to change;
- unit/integration/contract/E2E/migration/concurrency/performance tests as relevant;
- validation commands and required environment;
- assumptions, risks, rollback/migration needs, and out-of-scope work;
- approval state and external effects.

Keep the plan small enough to revise when new repository evidence appears.
